# StreamHub

StreamHub - учебный backend-проект на Go для управления каталогом видеоконтента. Проект демонстрирует разработку REST API, работу с PostgreSQL, кеширование через Redis, обмен событиями через NATS и контейнеризацию с Docker.

## Возможности

- REST API для управления контентом.
- Создание, получение, обновление и удаление записей.
- Поиск и фильтрация каталога.
- Сортировка и пагинация.
- PostgreSQL для постоянного хранения данных.
- Redis для кеширования результатов каталога.
- NATS JetStream для событий о создании, обновлении и удалении контента.
- Проверка состояния приложения и доступности базы данных.
- Unit-тесты и интеграционные тесты.
- Docker Compose для локального запуска.
- GitHub Actions для автоматической проверки кода.

## Технологии

- **Go** - backend и REST API.
- **PostgreSQL** - основная база данных.
- **Redis** - кеширование.
- **NATS JetStream** - события между компонентами.
- **Docker и Docker Compose** - запуск окружения.
- **GitHub Actions** - CI.

## Архитектура

Приложение построено как модульный монолит: HTTP-обработчики, бизнес-логика, репозитории, кеш и публикация событий разделены на отдельные компоненты внутри одного Go-приложения.

PostgreSQL хранит контент, Redis ускоряет чтение каталога, а NATS JetStream используется для публикации событий.

Подробнее: [Архитектура](docs/architecture.md).

## Запуск через Docker

Клонируйте репозиторий и перейдите в каталог проекта:

```bash
git clone https://github.com/AlbertSalimov/StreamHub.git
cd StreamHub
```

Запустите сервисы:

```bash
docker compose up --build -d
```

Проверьте состояние контейнеров:

```bash
docker compose ps
docker compose logs -f api
```

Проверка API:

```bash
curl http://localhost:8080/healthz
curl http://localhost:8080/readyz
```

Остановка:

```bash
docker compose down
```

Данные PostgreSQL хранятся в Docker volume и сохраняются при обычной остановке контейнеров.

## Запуск тестов

Unit-тесты:

```bash
go test ./...
```

Статический анализ:

```bash
go vet ./...
```

Проверка гонок данных:

```bash
go test -race ./...
```

Интеграционные тесты требуют отдельной тестовой PostgreSQL и переменной `TEST_DATABASE_URL`. Инструкции находятся в документации API и тестов.

## REST API

Базовый URL: `http://localhost:8080`.

| Метод  | Endpoint               | Назначение                                    |
| ------ | ---------------------- | --------------------------------------------- |
| GET    | `/healthz`             | Проверка работы процесса                      |
| GET    | `/readyz`              | Проверка готовности и соединения с PostgreSQL |
| POST   | `/api/v1/content/`     | Создание контента                             |
| GET    | `/api/v1/content/`     | Получение каталога                            |
| GET    | `/api/v1/content/{id}` | Получение записи по UUID                      |
| PUT    | `/api/v1/content/{id}` | Обновление записи                             |
| DELETE | `/api/v1/content/{id}` | Удаление записи                               |

Параметры поиска, фильтрации, сортировки и пагинации описаны в [документации API](docs/api.md).

## Переменные окружения

Основные настройки:

| Переменная        | Назначение                    |
| ----------------- | ----------------------------- |
| `HTTP_ADDR`       | Адрес HTTP-сервера            |
| `DATABASE_URL`    | Строка подключения PostgreSQL |
| `REDIS_ADDR`      | Адрес Redis                   |
| `REDIS_PASSWORD`  | Пароль Redis                  |
| `REDIS_DB`        | Номер Redis DB                |
| `REDIS_CACHE_TTL` | Время жизни кеша              |
| `NATS_URL`        | Адрес сервера NATS            |

Пример для локального запуска находится в `.env.example`.

## Ограничения учебной версии

- Проект использует модульный монолит, а не отдельные микросервисы.
- Доставка событий и запись в PostgreSQL не объединены атомарной транзакцией.
- Redis используется как кеш, а не как основное хранилище.
- Аутентификация, авторизация, лимитирование запросов и production-настройки безопасности требуют отдельной реализации.
